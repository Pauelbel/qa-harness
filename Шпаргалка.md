## Создать проект

Команда создаёт заготовку проекта: `conftest.py`, `config.yaml`, `pytest.ini`,
`requirements.txt` и по рабочему тесту на каждый выбранный компонент. Существующие
файлы она не перезаписывает.

```powershell
qa-core init                                          # текущая папка, компоненты http и allure
qa-core init мой-проект --components http,excel,allure
python -m qa_core init                                # если команда qa-core не найдена
```

Компоненты: `http`, `db`, `excel`, `odata`, `allure`, `ui`. Пошаговая инструкция
для новичка — в [Начало.md](Начало.md).

## Подключение

Ставьте только нужное (подробности — в README):

```powershell
python -m pip install "qa-core[http,db,excel,odata,allure] @ git+https://github.com/Pauelbel/qa-harness.git"
```

`conftest.py` в корне проекта. Оставьте только нужные плагины:

```python
pytest_plugins = [
    "qa_core.pytest_plugins.logging",           # логи в консоль и в logs/
    "qa_core.pytest_plugins.allure_reporting",  # логи упавшего теста в Allure
    "qa_core.pytest_plugins.playwright",        # фикстура browser_page
]
```

## HTTP

Набор `http`. Клиент пишет в лог метод, адрес, статус и время, а значения
параметров вроде `token` и `password` заменяет на `***`.

```python
from qa_core.clients.http import BaseHttpClient

def test_get_items():
    with BaseHttpClient() as http:
        response = http.get("https://service.example/api/items", timeout=10)

    response.raise_for_status()
    assert response.json()
```

- Методы: `get`, `post`, `put`, `delete`, аргументы как у `requests`.
- Если не указать `timeout=`, запрос ждёт 30 секунд (меняется в секции `http`).
  `timeout=None` отключает ограничение.
- Возвращается обычный `requests.Response`.
- Свою сессию передают так: `BaseHttpClient(session=my_session)`.
- Другой файл настроек: `BaseHttpClient(config_path="configs/test.yaml")`.

Авторизацию и адреса держите в проектном клиенте поверх `BaseHttpClient`:

```python
class MyApiClient:
    def __init__(self, base_url: str, token: str) -> None:
        self.base_url = base_url.rstrip("/")
        self.headers = {"Authorization": token}

    def get_items(self):
        with BaseHttpClient() as http:
            return http.get(f"{self.base_url}/api/items", headers=self.headers)
```

## PostgreSQL

Набор `db`. Соединение открывается на один запрос и закрывается само.

```python
from qa_core.clients.postgres import PostgresClient

def test_new_orders_exist():
    db = PostgresClient(dbname="app", user="tester", password="secret", host="db.example")

    rows = db.fetch_all("SELECT id FROM orders WHERE status = %s", ["new"])

    assert rows
```

Значения подставляйте только через `%s` и список параметров, не склеивайте
SQL строкой.

## Excel

Набор `excel`. Работает в два шага: `ExcelSource` получает файл,
`ExcelDataQualityChecker` его проверяет.

```python
from qa_core.checks.excel import ExcelDataQualityChecker
from qa_core.sources.excel import ExcelSource

def test_report(report_api, tmp_path):
    # 1. Получить файл (из HTTP-ответа; можно ExcelSource.from_path("a.xlsx"))
    response = report_api.download_report()
    report = ExcelSource.from_response(response, tmp_path / "report.xlsx")

    # 2. Проверить
    checker = ExcelDataQualityChecker(report.path)
    checker.check_filename(actual_name=report.original_filename, expected_suffix=".xlsx")
    checker.check_columns(["ФИО", "Дата"], strict_order=True)
    checker.check_required(["ФИО", "Дата"])
    checker.check_date("Дата")

    # 3. Завершить: упадёт один раз со всеми найденными ошибками
    checker.assert_valid()
```

Проверки можно писать цепочкой: `checker.check_required([...]).check_date("Дата")`.
Ошибки копятся, и `assert_valid()` показывает все сразу, со строками и примерами
значений. Поэтому `assert_valid()` вызывайте в конце каждого теста.

| Метод | Что проверяет |
| --- | --- |
| `check_columns(список, strict_order=False)` | Есть нужные колонки, нет лишних, порядок (по желанию) |
| `check_required(колонки)` | Ячейки не пустые |
| `check_text(колонка)` | Значения — текст |
| `check_date(колонка, fmt="%d.%m.%Y")` | Даты в нужном формате |
| `check_date_period(колонка)` | Период «дата - дата» |
| `check_is_numeric(колонка)` | Значения — числа |
| `check_integer(колонка)` | Значения — целые числа |
| `check_range(колонка, min_value=, max_value=, min_inclusive=, max_inclusive=)` | Число в диапазоне |
| `check_decimal_places(колонка, max_decimal_places=2)` | Не больше N знаков после запятой |
| `check_percentage(колонка, max_decimal_places=2)` | Процент со знаком `%` |
| `check_enum(колонка, ("Да", "Нет"))` | Значение из списка допустимых |
| `check_regex(колонка, шаблон, сообщение)` | Значение подходит под регулярное выражение |
| `check_cost_calculation(часы, ставка, стоимость)` | Стоимость равна часам × ставке |
| `check_no_fully_empty_columns(колонки)` | Нет полностью пустых колонок |
| `check_no_duplicate_rows(колонки)` | Нет одинаковых строк |
| `check_filename(...)` | Имя файла: точное, по шаблону или по расширению |
| `assert_valid()` | Выбрасывает ошибку, если что-то найдено |

Статистика без ошибок:

```python
row_count = checker.get_row_count()
statistics = checker.get_fill_statistics(["ФИО", "Дата"])  # таблица pandas
```

Подробности каждого метода — в его docstring.

## OData

Набор `odata`. Проверки работают с уже полученными данными и сами запросов не
отправляют. Они мягкие (на базе `pytest-check`): тест не останавливается на
первой ошибке, а показывает все.

```python
from qa_core.checks.odata import OdataAssertions

def test_orders(response):
    items = response.json()["value"]

    OdataAssertions.response_not_empty(items)
    OdataAssertions.top_limit(items, 10)
    OdataAssertions.filter_eq(items, "Status", "Draft")
```

| Метод | Для чего |
| --- | --- |
| `response_not_empty(items)` | В `value` есть записи |
| `schema(items, МодельPydantic)` | Каждая запись подходит под модель |
| `select_property(items, поле)` | `$select`: поле заполнено хотя бы в одной записи |
| `select_strict(items, разрешённые_поля)` | `$select`: нет лишних полей |
| `filter_eq`, `filter_ne`, `filter_contains` | `$filter`: равно, не равно, содержит |
| `filter_date_range(...)` | `$filter`: даты в диапазоне |
| `top_limit(items, N)` | `$top`: записей не больше N |
| `skip_consistency(первая, после_skip, N)` | `$skip`: страница сдвинута на N |
| `count_present(ответ)` | `$count`: счётчик есть в ответе |
| `expand_field(items, поле)` | `$expand`: вложенные данные на месте |
| `orderby(items, поле, reverse=False)` | `$orderby`: порядок сортировки |

## Браузер

Набор `ui`, плагин `playwright`. Один раз скачайте браузер:

```powershell
python -m playwright install chromium
```

Тесту доступна готовая страница `browser_page`. Браузер запускается один раз на
весь запуск, а каждый тест получает чистую страницу. При падении теста к Allure
прикладываются скриншот и trace.

```python
from playwright.sync_api import Page

def test_home_page(browser_page: Page):
    browser_page.goto("https://service.example")
    assert browser_page.title() == "Service"
```

**Войти один раз на весь запуск.** По умолчанию каждый тест получает чистую
страницу. Чтобы не логиниться в каждом тесте, переопределите фикстуру
`qa_storage_state`: она возвращает сохранённое состояние браузера (cookies), и
страница каждого теста начинается уже со входом. Скриншот и trace при падении
остаются.

```python
import pytest
from playwright.sync_api import Browser

@pytest.fixture(scope="session")
def qa_storage_state(qa_browser: Browser) -> dict:
    context = qa_browser.new_context()
    login(context.new_page(), url, user, password)  # ваша функция входа в этом же файле
    state = context.storage_state()
    context.close()
    return state
```

Локаторы пишите прямо в тестах, а повторяющееся действие (вход) выносите в
обычную функцию в том же файле: отдельные файлы Page Object не нужны. Полный
пример с демо-сервером: [test_06_ui_login.py](examples/test_06_ui_login.py).

Размер окна, движок и режим без окна задаются в секции `browser` файла
`config.yaml` (см. [Конфиг](#конфиг)). Чтобы взять настройки из другого места,
переопределите фикстуру `qa_browser_settings` в своём `conftest.py` с
`scope="session"`.

## Предусловия и постусловия

Данные для теста (заказ, проект, пользователь) создавайте через API и удаляйте
после теста фикстурой с `yield`. Код после `yield` выполняется всегда, даже если
тест упал. Отдельная система предусловий не нужна.

```python
from uuid import uuid4

@pytest.fixture
def order(api):
    order = api.create_order(title=f"autotest-{uuid4().hex[:8]}")  # предусловие
    yield order
    api.delete_order(order["id"])                                  # постусловие

def test_order_visible(browser_page, order):
    browser_page.goto(...)
    expect(browser_page.get_by_text(order["title"])).to_be_visible()
```

Правила:
- имя данных уникально (префикс `autotest-` и случайный хвост), так тесты не мешают
  друг другу, а оставшееся после аварийного запуска легко найти и удалить;
- ошибка очистки пишется в лог и не затирает настоящую причину падения теста;
- если в тесте нужно несколько объектов, используйте фабрику: фикстуру, которая
  возвращает функцию создания и удаляет всё созданное в конце;
- БД используйте для проверок и для того, что нельзя создать через API: запись
  в обход бизнес-логики может создать невозможное состояние.

Полный пример с демо-сервером, фабрикой и проверкой, что мусор не остался:
[test_05_preconditions.py](examples/test_05_preconditions.py).

## Allure и логи

Плагины `logging` и `allure_reporting` не требуют кода в тестах.

```powershell
python -m pytest --alluredir=allure-results --qa-environment=stage
```

- Логи пишутся в консоль и в файл `logs/pytest_<окружение>.log`.
- При падении теста его логи прикладываются к отчёту Allure.
- `--qa-environment` (или переменная `TEST_ENV`) подписывает окружение в логах и
  в `environment.xml`.

Плагин задаёт только значения по умолчанию, ваши настройки главнее. Для отладки:

```powershell
# Подробные логи в консоли (в том числе urllib3 и других библиотек)
python -m pytest --log-cli-level=DEBUG

# Свой файл лога вместо logs/pytest_<окружение>.log
python -m pytest --log-file=debug.log

# Без логов в консоли
python -m pytest -o log_cli=false
```

Те же параметры можно записать в `pytest.ini` (`log_cli_level = DEBUG`).

Декораторы `epic`, `feature`, `story`, `title` и шаги `allure.step` пишутся в
ваших тестах: они описывают смысл сценария.

## Секреты

`SecretStore` читает пароли и токены из переменных окружения (по умолчанию) или
из Vault. Источник выбирается через `SECRETS_SOURCE=env` или `vault`.

```python
from qa_core.secrets import SecretStore

secrets = SecretStore()
token = secrets.get("API_TOKEN")                          # переменная API_TOKEN
token = secrets.get("API_TOKEN", env_key="STAGE_API_TOKEN")  # в env другое имя
```

Если ключа нет, будет `SecretError` с его именем. Для Vault нужны набор `vault`
и переменные из [README](README.md#секреты).

## Конфиг

Файл `config.yaml` необязателен. Без него действуют значения по умолчанию.

```yaml
http:
  timeout: 30
  max_logged_response_body_length: 2000
  sensitive_query_parameters: [token, api_key, password]

browser:
  engine: chromium
  headless: true
  width: 1920
  height: 1080
  ignore_https_errors: true
```

Читать свою секцию в своём коде:

```python
from qa_core.config import load_section

settings = load_section("browser", BrowserSettings)       # из ./config.yaml
settings = load_section("browser", BrowserSettings, "configs/test.yaml")
```

## Свой плагин

Плагин — обычный модуль pytest. Пример: плагин, которому нужна своя секция
`jira` в `config.yaml`.

`my_project/jira_plugin.py`:

```python
import pytest
from pydantic import BaseModel, ConfigDict

from qa_core.config import load_section


class JiraSettings(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)

    url: str = "https://jira.example"
    project: str = "AG"


@pytest.fixture(scope="session")
def jira_settings() -> JiraSettings:
    return load_section("jira", JiraSettings)
```

`config.yaml`:

```yaml
jira:
  project: QA
```

Подключение в проекте, `conftest.py`:

```python
pytest_plugins = [
    "qa_core.pytest_plugins.logging",
    "my_project.jira_plugin",
]
```

Теперь любой тест может взять фикстуру `jira_settings`.

Чтобы оформить плагин отдельным устанавливаемым пакетом, добавьте в его
`pyproject.toml` зависимость на `qa-core` и точку входа:

```toml
[project.entry-points.pytest11]
qa_core_jira = "qa_core_jira.plugin"
```

После `pip install` пакета строка в `pytest_plugins` не нужна.
