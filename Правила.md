# Правила написания тестов

Короткие правила, чтобы тесты команды выглядели одинаково и читались без вопросов.
Образцы лежат в [examples/](examples/), заготовки новых тестов — в [templates/](templates/).

## Структура проекта

```text
tests/
  api/           тесты API
  db/            тесты базы данных
  ui/            тесты в браузере
pages/           Page Object: по классу на страницу
clients/         клиенты вашей системы поверх клиентов ядра
conftest.py      подключение плагинов и общие фикстуры проекта
config.yaml      настройки
```

Новый тест начинайте с копии шаблона из [templates/](templates/): структура в нём уже задана.
Подготовка для одного файла лежит в `conftest.py` рядом с ним, для многих — в `conftest.py`
проекта. В ядро уходит только то, что не знает адресов, SQL и локаторов вашей системы.

Один файл — одна тема (эндпоинт, отчёт, страница). Имя файла и теста начинается с `test_`
и говорит, что проверяется: `test_orders_filter_by_status`.

## Один тест — одна мысль

Тест проверяет одну вещь. Структура всегда одна: подготовка → действие → проверка.

## Маркеры

Помечайте тест тем, чем он является: `api`, `ui`, `db`; быстрые проверки «система жива» —
ещё и `smoke`. Для всего файла: `pytestmark = pytest.mark.ui`. Запуск части:
`pytest -m smoke`, `pytest -m "api and not ui"`.

## Проверки

- Простая проверка — `assert`, сообщение пишите по-русски: что именно не так.
- Чтобы увидеть все ошибки сразу, а не первую, берите мягкие проверки (`OdataAssertions`).
- В проверках Excel вызывайте `checker.assert_valid()` в конце теста: он соберёт все ошибки.

## Данные для теста

- Создавайте данные через API и удаляйте после теста фикстурой с `yield`
  ([пример](examples/test_02_preconditions.py)).
- Имя тестовых данных уникальное: префикс `autotest-` и случайный хвост.
- Не рассчитывайте на данные от прошлого запуска или другого теста.
- В БД пишите только если иначе нельзя: запись в обход приложения может создать невозможное состояние.

## Секреты

- Пароли, токены и ключи не пишутся в код и не попадают в Git: переменные окружения или Vault
  (`SecretStore`). Файл `.env` уже в `.gitignore`.

## Ожидания и время

- Не используйте `time.sleep`. Ждите событие: `expect(...).to_be_visible()`.
- У каждого запроса есть таймаут (по умолчанию 30 секунд). Для долгих операций:
  `http.post(url, json=..., timeout=300)`.

## UI-тесты

- Работа со страницей спрятана в Page Object (`pages/`): в тесте нет локаторов и кликов,
  только вызовы методов ([пример](examples/test_03_ui_page_object.py)).
- Ищите элементы по роли и тексту (`get_by_role`, `get_by_label`), не по CSS-цепочкам.
- Вход делайте один раз на запуск, переопределив фикстуру `qa_storage_state`.

## Allure (необязательно)

Тест и шаблоны не должны требовать Allure. Если он подключён, можно добавлять
`@allure.title(...)` и `allure.step(...)` в своих тестах, но тогда `allure-pytest` обязателен
для всего проекта.

## Когда тест упал

1. Прочитайте сообщение об ошибке: оно называет значение или строку.
2. Запустите с подробными логами: `python -m pytest --log-cli-level=DEBUG путь_к_тесту`.
3. Для UI откройте скриншот и trace в `test-artifacts/`.
