# Правила написания тестов

Короткие правила, чтобы тесты команды выглядели одинаково и читались без вопросов.
Примеры кода — в папке [examples](examples/README.md).

## Структура проекта

```text
tests/
  api/           тесты API
  database/      тесты базы данных
  frontend/      тесты в браузере
conftest.py      подключение плагинов и общие фикстуры
config.yaml      настройки
```

Один файл — одна тема (один эндпоинт, один отчёт, одна страница). Имя файла начинается с
`test_`, имя теста — с `test_` и описывает, что проверяется: `test_orders_filter_by_status`.

## Один тест — одна мысль

Тест проверяет одну вещь. Название тестов в Allure (`@allure.title`) читается как предложение
по-русски и объясняет, что должно быть: «Фильтр по статусу возвращает только черновики».

## Оформление под Allure

```python
@allure.epic("API Бэкенд")          # крупная область
@allure.feature("/api/v1/orders")   # раздел
@allure.story("Проверка запросов")  # сценарий
@allure.title("Проверка параметра $top")
def test_orders_top(...):
    with allure.step("Отправить запрос"):
        ...
```

- Шаги `allure.step` оформляйте для действий, которые стоит видеть в отчёте.
- Минимум для теста — `epic` и `title`. Остальное добавляйте по ситуации.

## Проверки

- Простая проверка — `assert`.
- Если нужно показать все ошибки сразу, а не остановиться на первой, используйте мягкие
  проверки (`OdataAssertions` и `pytest-check`).
- В проверках Excel вызывайте `checker.assert_valid()` в конце теста: он соберёт все найденные
  ошибки в одно сообщение.
- Сообщение об ошибке пишите по-русски и так, чтобы было понятно, что именно не так.

## Данные для теста

- Создавайте данные через API и удаляйте после теста фикстурой с `yield`
  ([пример](examples/test_05_preconditions.py)).
- Имя тестовых данных уникальное: префикс `autotest-` и случайный хвост.
- Не рассчитывайте, что данные остались от прошлого запуска или другого теста.
- В БД пишите только если иначе нельзя: запись в обход приложения может создать невозможное состояние.

## Секреты

- Пароли, токены и ключи не пишутся в код и не попадают в Git. Они лежат в переменных окружения
  или в Vault (`SecretStore`).
- Файл `.env` добавлен в `.gitignore`.

## Ожидания и время

- Не используйте `time.sleep`. Ждите конкретного события: `expect(...).to_be_visible()`,
  `page.wait_for_url(...)`.
- У каждого запроса есть таймаут. По умолчанию 30 секунд; для долгих операций передайте свой:
  `http.post(url, json=..., timeout=300)`.

## UI-тесты

- Локаторы пишите прямо в тесте. Повторяющееся действие (например, вход) вынесите в обычную
  функцию в этом же файле, отдельные классы страниц не нужны.
- Вход делайте один раз на запуск через `qa_storage_state`
  ([пример](examples/test_06_ui_login.py)).
- Ищите элементы по роли и тексту (`get_by_role`, `get_by_label`), а не по сложным CSS-цепочкам.

## Что делать, когда тест упал

1. Прочитайте сообщение об ошибке: оно на русском и называет колонку, строку или значение.
2. Запустите ещё раз с подробными логами: `python -m pytest --log-cli-level=DEBUG путь_к_тесту`.
3. Для UI-теста откройте скриншот и trace, они прикладываются к Allure-отчёту.
