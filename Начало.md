# С чего начать

Страница для тех, кто впервые пишет автотесты. За 15 минут вы запустите готовые
примеры, создадите свой проект и запустите свой первый тест. Читать весь README
не нужно.

## Что нужно заранее

- Python 3.11 или новее. Проверка: в PowerShell выполните `python --version`.
- Любой редактор кода (подойдёт VS Code).
- Доступ к репозиторию `qa-harness`.

## Шаг 1. Запустите готовые примеры

Так вы убедитесь, что всё работает, и увидите, как выглядят тесты.

```powershell
# 1. Откройте папку qa-harness и создайте окружение (один раз)
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# 2. Поставьте qa-core со всеми компонентами
python -m pip install -e ".[all]"

# 3. Запустите примеры
python -m pytest examples
```

В конце должно быть `passed` и ни одного `failed`. Пара тестов будет `skipped`:
они ждут браузер или базу данных, это нормально.

Чтобы запустить примеры с браузером:

```powershell
python -m playwright install chromium   # один раз
$env:EXAMPLE_UI='1'; python -m pytest examples
```

## Шаг 2. Создайте свой проект

Команда `qa-core` появилась после шага 1, поэтому не закрывайте то окно PowerShell, где
активировано окружение (в начале строки видно `(.venv)`). Перейдите в пустую папку
будущего проекта и выполните:

```powershell
cd путь\к\новому\проекту
qa-core init --components http,allure
```

Если команда `qa-core` не найдена, используйте `python -m qa_core init --components http,allure`.

Команда создаст файлы и подскажет следующие шаги. Список компонентов, которые можно
перечислить через запятую:

| Компонент | Для чего |
| --- | --- |
| `http` | запросы к API |
| `db` | запросы к PostgreSQL |
| `excel` | проверка Excel-отчётов |
| `odata` | проверка ответов OData |
| `allure` | красивый отчёт о запуске |
| `ui` | тесты в браузере |

Что появится в проекте:

```text
conftest.py          подключение плагинов (логи, Allure, браузер)
config.yaml          настройки (необязательный файл)
pytest.ini           где искать тесты
requirements.txt     что установить
tests/               ваши тесты, в начале по одному примеру на компонент
```

Затем создайте для проекта своё окружение и установите зависимости (команды покажет
`init`). Для установки `qa-core` из репозитория нужен доступ к нему из терминала:

```powershell
deactivate                      # выйти из окружения qa-harness
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

## Шаг 3. Запустите и поправьте свой первый тест

```powershell
python -m pytest
```

Откройте `tests/test_example_http.py`. Он ходит на тестовый адрес `https://example.com`.
Замените адрес на адрес вашего сервиса и запустите снова. Первый тест готов.

## Шаг 4. Посмотрите результат

- **В консоли:** во время запуска видны строки с логами: адрес запроса, код ответа и
  время. Значения `token`, `password` и похожих параметров в адресе запроса заменены на `***`.
- **В файле:** весь подробный лог сохраняется в папку `logs/`.
- **Allure-отчёт** (если выбрали `allure`): запустите
  `python -m pytest --alluredir=allure-results`, затем `allure generate --single-file -c ./allure-results`.
  Получится один HTML-файл, его можно открыть в браузере.
- **Подробные логи для поиска ошибки:** `python -m pytest --log-cli-level=DEBUG`.

## Словарик

| Слово | Что значит |
| --- | --- |
| Тест | функция, имя которой начинается с `test_`. Она падает, если проверка не прошла |
| `assert` | проверка. `assert response.status_code == 200` — «код ответа должен быть 200» |
| Фикстура | подготовка для теста. Тест просто пишет её имя в аргументах и получает готовое значение |
| Плагин | готовая возможность, подключаемая в `conftest.py`: логи, отчёты, браузер |
| Allure | инструмент красивых отчётов о запуске |
| Окружение | стенд, на котором идёт запуск: dev, stage, prod |
| Секрет | пароль или токен. В коде теста их не пишут, их читают из переменных окружения |

## Если что-то не работает

| Что видите | Что делать |
| --- | --- |
| `No module named 'pandas'` (или `requests`, `allure`, `playwright`) | не поставлен нужный компонент: добавьте его в `requirements.txt` и выполните установку заново |
| `Файл конфигурации не найден` | запуск не из той папки. Запускайте `python -m pytest` из папки, где лежит `config.yaml`. Если файл вам не нужен, предупреждение можно игнорировать |
| `command not found: qa-core` | используйте `python -m qa_core init ...` |
| Тест долго «висит» | запрос ждёт ответ. По умолчанию это 30 секунд, потом тест упадёт с ошибкой |
| Браузер не запускается | выполните `python -m playwright install chromium` |
